    Register & onboard

    Register before you build

    Every AI asset is registered in the Zion capability registry before development starts (gate G1). The duplicate check points owners to what already exists, so grp1, grp2 and grp3 extend one function instead of building three.

    The registration form

    Six short steps, about five minutes. Each step maps to a gate, so a registered asset is already part-way to being listed. The form checks for duplicates as you type.

    Onboarding pipeline

    Where each asset sits on its way to the catalog and to certification. Target: a new group onboards an existing asset in 2 days or less.

    Reuse & value

    Build once, reuse everywhere, and prove it

    Reused functions are benchmarked and certified, not copied. Value is counted only where it is measured. Full scoring lives in the benchmark dashboard (wf6).

    Certification ladder

    Composite of six weighted dimensions; every gate must pass. Highest composite that passes all gates becomes the Sol PE standard.

      How the hub is built

      One asset record drives the catalog, the STLC map, the onboarding pipeline and the value views. The benchmark service (wf6) and the Excel workbook stay the source of truth for scores until the live feed is wired.

      Asset record

      Registry schema, one per solution, agent, skill, prompt pack, logic, tool or dataset
      AiAsset {
  id: "shield.decode_host_log", type: "skill", version: "1.4.0"
  name, summary, tasks: ["decode a host log", …]
  parent: "SH", contains: [ids], relatedTo: [ids]
  owner: { group, site, person, aiChampion }
  stlc: { primary: [6], supporting: [5] }, l3Capability: "6.c"
  products: [eMMC|UFS|Client SSD|PSSD|Enterprise SSD|DC SSD]
  specs: [NVMe|SATA|UFS|eMMC|NVMe-MI|OAM|OCP|SPDM|PLDM|MCTP|TCG]
  interfaces: { portal, chat, ide, api: openapiUrl, mcp: toolName }
  dependsOn: ["llm-gateway", "log-parser", …]
  data: { classes: [...], llmRoute: "zion-gateway", humanGate: true }
  lifecycle: registered|dup-check|contract|integration|listed
  status: Live|Pilot|Build|Planned
  benchmark: { goldenSet, round, composite, gates: {G1..G6}, tier }
  value: { hoursPerMonth, acceptRate, mau, groupsUsing, sitesUsing }
  docs: { readme, ioContract, modelCard, runbook, benchmarkReport }
}

      Build notes

      • Each view on this page maps to one route; each card, matrix and pipeline is a reusable component fed by AiAsset.
      • Duplicate check on register: embedding similarity on name, summary and tasks, plus same L3 capability and STLC phase. Over 70% similarity routes to the review board.
      • Value numbers only appear when the asset reports them; unmeasured assets show a hatched bar, never an estimate.
      • Site federation starts read-only: HQ's catalog appears in Discover with a site badge; reuse requests become joint backlog items.
      • Confluence: Insert → Other Macros → HTML, paste this file. Filters, drawer and wizard need scripts enabled in the macro.
      • Framework follows the Zion portal standard; the layout uses no external libraries.
